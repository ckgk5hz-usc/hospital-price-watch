# Hospital Price Watch

An independent companion site to Prof. Glenn Melnick's USC Center for Health Financing, Policy, and Management (sites.usc.edu/improvinghealth). Tracks hospital pricing, consolidation, and affordability research.

**Status: prototype, not live.** Structure borrows from Health Care Cost Institute and Yale's Health Care Affordability Lab; content is entirely the Center's own real, published research. UI/UX is expected to be fully revamped before launch — treat the current design as a content/structure placeholder, not a final look.

## Stack

Static HTML/CSS/vanilla JS, single `index.html`. No build step. Intended for GitHub Pages, pointed at a purchased domain once one is chosen.

## Not done yet

- No real domain/DNS.
- No HCAI Dataset Explorer (interactive hospital map, chart presets, regression — see project notes).
- No news/fact-checking comparison module.
- UI/UX redesign planned before launch.

## News pipeline (news.html)

`news.html` is generated by `tools/build.py` (run from the repo root) from four data files. What is automated and what is by hand:

| Section | Source | Automated? |
|---|---|---|
| Current news: National, California, By state | `data/news.json`, written by `tools/news/fetch_news.py` from public RSS feeds (KFF Health News, KFF, Healthcare Dive, Fierce Healthcare, Becker's, Health Affairs, CHCF, plus keyword-filtered STAT, Axios, Commonwealth Fund, CalMatters) | Yes, daily via `.github/workflows/news.yml` |
| External briefs (California only) | `data/external_briefs.json` | No. Added by hand after opening and reading each item |
| Issue briefs (the Center's own) | `BRIEFS` in `tools/content.py` | No |
| Interviews, talks, events | `data/events.json` | No. `tools/news/scan_events.py` lists possible new ones in `data/events_candidates.json` for review; nothing is published until copied by hand |
| Hand-picked news that no feed carries | `data/news_curated.json` | No |

**How verification works.** Displayed text (title, link, source, date, snippet) is copied from the feed as published. No model writes or edits it.
1. Keyword rules decide relevance, place (national, California, or one state) and topics.
2. If the repo secret `ANTHROPIC_API_KEY` is set, a small model (claude-haiku-5-5) double-checks each new item and returns labels only: relevant or not, place, state, topics, reliable or not. It can drop an item or fix its labels. Decisions are cached by URL in `data/news_cache.json`. Each item records `verified_by`: `llm-verified` or `rules-only`.
3. New links are checked mechanically; 404/410 items are dropped, and bot-blocked links (401/403/429) are kept as unchecked.

**What a person must do.** Add the secret in GitHub: repo Settings, Secrets and variables, Actions, New repository secret, name `ANTHROPIC_API_KEY`. Without it the pipeline still runs, in `rules-only` mode. Nobody but the repo owner can add it.

**Run it locally.** `python3 tools/news/fetch_news.py --no-llm`, then `python3 tools/build.py`. Add `ANTHROPIC_API_KEY` in the environment to include the model check.

`.github/workflows/site-check.yml` runs `tools/check_site.py` on every push: data files must parse with no `Infinity`/`NaN`, and internal links in the pages must resolve.
